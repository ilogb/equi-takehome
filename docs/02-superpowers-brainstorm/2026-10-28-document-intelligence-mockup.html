Three layout decisions, with a recommendation each

Recommendations
  1. Search and its results: A, its own results page. Ask answers carry ranked tables and source links, and Simple results carry metadata, tags, a Drive path and similar documents. Both need full width, and a results URL lets Back return to the answer after opening a source document.
  2. Document view: A, file beside tabbed extraction. The Man AHL grid alone is 11 years by 13 columns and becomes 158 common rows, so stacking both views makes one very long pane.
  3. Data table: A, one row per number. This is the stored shape (fund · share class · period · measure), so every filter maps to a column. When two documents disagree, both rows stay visible and nothing is picked.

The rest of the design has no real layout choice: the connect flow is a fixed sequence, and the Library is a dense file table. Both are drawn once, in every state. Components are shadcn/ui (Button, Badge, Table with TanStack-style header, faceted filters and pagination, Tabs, ToggleGroup, Card, Alert, Progress, Skeleton, Tooltip, Popover + Command, Dialog, Sheet, DropdownMenu, Breadcrumb, Avatar, Separator, RadioGroup, Checkbox, Input, Textarea), with lucide icons.

Pros: no new screen, and Simple works like a Library filter. Cons: the same box does different things on each screen, similar documents and snippets have no place, and the Ask sheet covers the Data table.

Why A. Every number in an answer links to its source document, so people will move back and forth between the answer and the documents. A page keeps the answer at a URL, which B loses when it closes and C squeezes into a sheet. A also keeps the box behaving the same on every screen, matching the brainstorm’s “one unified search”. It is the least to build: one route, with Library and Data left as plain screens. A typeahead under the box could be added later without changing the page.

Decision 2 · How do printed tables and common rows sit beside the file?

The app doesn’t keep a copy of the file. The left pane streams it from Google Drive each time it’s opened. The right pane shows what the app stored: tables as printed and the same numbers as common rows, in Tabs. Metadata, tags, the Drive path and a manual Re-extract button sit above both. A file is processed once, and edits made to it in Drive are ignored unless someone presses Re-extract.
